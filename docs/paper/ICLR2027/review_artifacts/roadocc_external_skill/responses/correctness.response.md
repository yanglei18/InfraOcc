# Correctness

## Scope and Evidence

This correctness-stage artifact uses the canonical OCR Markdown and evidence manifest for `roadocc_external_skill`. The manifest states that the full PDF pages 1-19 were retained because the supplement contains route-supervision and diagnostic evidence needed for scoring. I ignore earlier review artifacts and assess the method from the OCR evidence only.

## Technical Soundness

RoadOcc’s central decomposition is mathematically coherent: Eq. 1 defines a velocity-guided historical read, Eq. 7 defines a supervised Persist/Transport/Refresh target, and Eq. 8 makes source choice a softmax competition rather than independent gates. This is a defensible formulation for fixed roadside occupancy because rigid alignment is sufficient for static layout but not for moving dynamic objects. The paper correctly separates the address-estimation question, handled by VVE, from the source-admissibility question, handled by P/T/R routing.

Rigid retrieval is sound as a candidate source but unsound as a universal temporal strategy. The paper’s own motivation and Table 5 support this: the rigid read obtains Dyn. 30.10, Nxt. 29.44, dM 2.146, and DSR 57.84, while VVE read improves all four values. Treating rigid memory as the Persist candidate in Eq. 7 is therefore appropriate; treating it as always valid would be wrong for moving objects.

Velocity-guided retrieval in Eq. 1 is algorithmically plausible under the fixed roadside setup and 0.5 s frame interval. The locally constant velocity assumption is reasonable as a short-horizon approximation, especially because the method predicts planar velocity in the common roadside frame and only uses it to backtrace historical support. The main limitation is that Eq. 1 cannot represent acceleration, turning with changing yaw, nonrigid pedestrian motion, or failures caused by occlusion and disocclusion. The Refresh route in Eq. 7 partly handles unsupported history, but it does not fix the underlying motion model when a wrong same-class historical support happens to exist nearby.

DCA selection is a sensible sparse-computation mechanism. Eq. 2 combines semantic discrepancy from a static reference with current dynamic probability, and Appendix C.1 expands this into Eqs. 16-18. This is appropriate for roadside scenes where dynamic voxels are sparse. The main risk is dependence on early provisional semantic predictions: if both the current and static heads miss a dynamic object, DCA may not allocate temporal reasoning there. The use of the maximum between discrepancy and dynamic probability mitigates but does not eliminate this failure mode.

The DCA cross-attention update in Eq. 3 is mostly sound, but its stochastic training threshold and deterministic inference threshold create a mild train-test mismatch. Appendix C.1 clarifies the depth-consistency factor in Eq. 19 and that deformable-attention weights are multiplied by depth consistency without renormalization. That is a valid design choice, but it means the magnitude of the update can shrink with depth inconsistency rather than preserve normalized attention mass. This should be acceptable if empirically stable, but it is not purely a selection operator.

The VVE correlation volume in Eq. 4 is a standard and reasonable local matching device. Appendix C.1 states that the volume has a 5x5 window, 25 channels, normalized operands, and is decoded with current and historical BEV embeddings. Table A2 reports the physical support at each scale. The paper is careful to say this window bounds only explicit matching evidence and that the recursive residual is not a hard speed bound. That avoids an incorrect complexity or speed-limit claim. The concern is not formal correctness but robustness: when the true correspondence is outside the local evidence window at finer scales, VVE must rely on the coarser prior and learned residual rather than direct local matching.

Recursive VVE in Eq. 5 is technically appropriate. Coarse-to-fine refinement lets the method estimate large low-resolution motion first and then refine boundaries. However, the blend coefficient is described as based on current dynamic support and valid history; Appendix C.1 further says the history branch weight is current dynamic support gated by history validity, not a calibrated measure of historic correspondence. This is an important limitation: the recursion can propagate a wrong coarse prior or ambiguous same-class match, and the blend does not itself certify that the historical feature is the correct source.

P/T/R target construction in Eq. 7 is the strongest algorithmic idea but also the most important correctness caveat. Appendix C.1 defines the native source address in Eq. 20 and states that support means same semantic class at the same height within a 3x3 XY neighborhood, with Boolean support and no instance-level tie-breaking. This makes the target valid for semantic source admissibility, not for instance correspondence. Nearby same-class vehicles can satisfy support for the wrong object. Therefore, the target is correct for the InfraOcc semantic occupancy label space, but it should not be interpreted as proving object identity tracking or instance-consistent temporal fusion. Appendix F explicitly confirms this distinction.

The GT-conditioned route diagnostic has a clear consequence. Figure A3, Figure 7, and Table A4 evaluate route decisions on valid GT dynamic voxels, deliberately separating routing from detection. This is useful for diagnosing source-choice behavior, but it inflates interpretability if read as an end-to-end detection or correspondence metric. Table A4 can show that the router prefers Persist/Transport/Refresh correctly on known dynamic support; it cannot show that the model finds all dynamic voxels, nor that Transport selects the same physical instance. The paper partially handles this by pairing the diagnostic with Dyn., Nxt., Direct MAVE, and DSR in Tables 3, 5, 6, A5, and A6.

Soft routing in Eq. 8 is mathematically preferable to hard route selection during fusion because gradients can flow through all three candidates and because uncertain cases can mix current and historical evidence. The softmax competition correctly enforces a source distribution. The limitation is interpretability: argmax route maps are diagnostics only, as the paper states. Any claim that a voxel strictly “used Transport” at inference should be read as an argmax summary of a soft mixture, not as the actual fused computation.

The FIFO history mechanism is plausible and well specified in Appendix C.1: each scale stores fused features and VVE priors, aligns slots rigidly, uses slot age for inverse-trajectory Transport addresses, masks invalid slots, and clears queues at scene boundaries. This is algorithmically sound for fixed-camera sequences. The remaining risk is compounding error because queues store model-fused features and cached priors, not immutable GT evidence. The paper’s controlled studies reduce this concern empirically but do not fully analyze long-horizon drift beyond the reported queue lengths.

The losses in Eq. 10 and Appendix C are well aligned with the method decomposition: semantic occupancy supervises the output, motion loss supervises the transport address, and route loss supervises source admissibility. The route loss is restricted to valid current dynamic voxels, which matches the P/T/R task but means route supervision is not a general voxel-wise temporal policy over static/free space. Equal P/T/R class weights help with rare Refresh cases, but Table A4 still shows Refresh precision is low, consistent with class rarity and uncertainty.

The metric definitions are mostly sound. Appendix B defines Direct MAVE over all valid GT dynamic voxels in Eq. 13, TP-MAVE over semantic true positives in Eq. 14, and DSR as micro recall in Eq. 15. This is a correct way to avoid the common error of celebrating low conditional motion error while missing many objects. Next Dyn. is also clearly distinguished from the radius-one hit score used in the backwarp visualization. The evaluation contract is therefore technically careful.

Practical scaling is reported but not fully settled. Eq. 6 uses TopK sparse selection, Appendix E reports the default token budgets \(K=[2000,512,128]\) and history samples \([8,4,2]\), and Table A5 shows saturation when doubling the token budget. This supports the claim that gains are not simply from expanding sparse capacity. Table A3 reports RoadOcc parameters as 78.69 and latency as TBD. I do not deduct for the TBD latency entry, per the user constraint and manifest note. The practical scaling concern is limited to memory and implementation complexity from per-scale FIFO queues, VVE priors, multi-slot routing, and correlation volumes; the paper gives enough budget details to make this assessable, but not enough completed latency evidence to judge deployment speed.
