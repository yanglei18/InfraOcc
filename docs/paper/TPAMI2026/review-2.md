# InfraOcc 数值审查

## 审查范围

本审查仅检查当前 TPAMI manuscript 源文件
`docs/TPAMI2026/local-git` 中可见的数值与论述。不使用实验日志、表格记录、
checkpoint 或配置文件作为证据。

## 结论

主结果表内部一致；多个消融表则不一致：其报告的 `mIoU_all` 无法由同一行的
动态和静态均值按论文自身的指标定义计算得到。这些行必须重算或删除后才能投稿。
大量以 `0` 和 `5` 结尾的小数构成审稿风险信号，但不能单独作为数值伪造的证据。

## 论文隐含的指标定义

实验设置将 `All` 定义为所有非 free 有效类别上的 mIoU，并将 bicycle、bus、car、
motorcycle、pedestrian 和 truck 定义为 6 个动态类别（`latex/4-exps.tex:18-27`）。
Table 2 列出了其余 8 个非 free 类别：`Other`、barrier、cone、driveable、sidewalk、
terrain、manmade 和 vegetation（`latex/tab/tab02-main-results.tex:29`）。相机 ProSD
行进一步表明 `Other` 被计入 `mIoU_sta`。

因此，论文展示的数值必须满足：

```text
mIoU_dyn = 6 个动态类别 IoU 的均值
mIoU_sta = 8 个静态类别 IoU 的均值，其中包括 Other
mIoU_all = (6 * mIoU_dyn + 8 * mIoU_sta) / 14
```

当三项指标均独立保留两位小数时，展示的 `mIoU_all` 与上式相差至多约 `0.01`。
更大的偏差属于算术矛盾，不能由正常舍入解释。

## 跨表与正文矛盾

### Table 3 与 Table 5：无静态抑制

相同条件被展示了两次：

| 位置 | gIoU | all | dyn | sta |
| --- | ---: | ---: | ---: | ---: |
| Table 3，`No static suppression` | 87.10 | 56.40 | 24.10 | 78.70 |
| Table 5，`No static suppression`，`alpha_init=0.0` | 83.10 | 55.40 | 27.10 | 76.70 |

Table 5 说明只改变衰减方式，且 `alpha_init=0.0` 表示关闭静态抑制。因此读者没有
理由将两行理解为不同实验。若 Table 3 还关闭了其他组件，必须在行名和表注中明确
写出。按当前写法，四个指标都应完全一致。

### 正文与表格

正文声称抑制将动态 mIoU “从 27.10 提升到 28.40”
（`latex/4-exps.tex:80-85`），但表中没有任何一行是 28.40：

- Table 5 的无抑制和固定抑制分别为 27.10 和 28.32。
- Table 3 的无静态抑制和仅抑制分别为 24.10 和 28.81。

因此，该句、Table 3 与 Table 5 不可能同时正确。

### 指标定义不完整

正文将 `mIoU_sta` 称为静态类别均值，却没有明确 `Other` 是否属于静态组。它必须
明确写入，因为只有将 `Other` 纳入，才能复现 Table 2 相机 ProSD 行的 `mIoU_sta`。
指标定义还应完整列出 14 个有效类别和 3 个排除类别，不能使用 “such as”。

## 小数末位模式：风险信号而非证据

Tables 3--9 共展示 132 个 `all`、`dyn` 和 `sta` 数值，其中 48 个（36.4%）以 `0`
或 `5` 结尾；仅看 `mIoU_all` 时，44 个数中有 15 个（34.1%）以 `0` 或 `5` 结尾。
在简单的独立且末位均匀假设下，预期比例为 20%。结合前述算术矛盾，这会使表格呈现
手工取整或手工拼接的观感。

不过，这种模式不能被当作数值伪造的证据：表格中的数值不是独立样本，保留两位小数
也不保证末位均匀。类似 Table 2 中 SparseOcc 对 motorcycle 的 `0.00` IoU 是可能的，
单独并非错误。需要处理的是末位模式与可验证的指标矛盾同时出现这一组合风险。

## 通过的检查

- Table 2 的每一行均在正常的两位小数舍入误差内满足上述公式。
- 默认行 `89.08 / 60.08 / 28.97 / 83.42` 在多张消融表中重复并不天然可疑；同一默认
  配置作为对照时可以合法重复出现。
- Tables 10--12 未展示足以运行相同算术检查的分组指标；其中与 Table 2 重复的 clean
  动态 mIoU 在内部是一致的。

## 投稿前必须修正

1. 从一次评测的完整 per-class IoU 向量自动生成每张表，不应分别手填 `all`、`dyn` 和
   `sta`。
2. 为 “No static suppression” 使用唯一的规范结果；如 Table 3 与 Table 5 确有额外组件
   差异，必须在行名中完整写出。
3. 在重新生成表格后，修正正文中的 “27.10 到 28.40” 表述。
4. 在 Metrics 段落中写明完整类别划分和计算公式。
5. 在投稿补充材料中提供最终的每类结果向量，使审稿人可以复核每个汇总指标。
